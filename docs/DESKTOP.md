# 桌面客户端（学习通 cxstudy）自动化说明

> 目标：让插件「桌面版」也能自动刷课/答题。以下是实测结论与当前实现。

## 一、可用的通道：Windows UI Automation + 内置 OCR

客户端是 Electron 43 / Chromium 150，但 **禁止外部调试**：

| 尝试 | 结果 |
| --- | --- |
| `--remote-debugging-port=9525` | 启动即退出，日志零增长（主动拦截） |
| `--remote-debugging-pipe` / `--inspect=9526` | 同上 |
| 修改 `app.asar` 的 index.js 注入调试开关 | 进程能起、CDP 能连，但 `Target.getTargets` 为空、不建窗口（应用自检拒绝） |
| `--force-renderer-accessibility` | 正常启动，UIA 能枚举出窗口与部分元素 |

所以桌面端只能走「截图/OCR + 鼠标键盘模拟」这条 UI 自动化路线（与网页版的 CDP 路线完全不同）。

## 二、驱动组成

| 文件 | 作用 |
| --- | --- |
| `desktop/uia2.ps1` | 批量动作脚本：一次 PowerShell 进程执行一组动作（click/wheel/key/paste/sleep/hash/ocr/shot/uia/scrolluia），输出 JSON |
| `lib/deskv2.mjs` | Node 侧封装：`actions()` 批量动作、`readRegion()` OCR、`hash()` 像素哈希、`click()/paste()/key()`、`launch()` |
| `lib/deskflow.mjs` | 业务流程：`goCourses()` → `openCourse(名称)` → `chapters()` → `openChapter(编号)` → `scrollDoc()` / `playVideo()` |
| `desktop/ocrapi.py` | 备用常驻 OCR（RapidOCR，约 3 秒/帧，仅在需要用 python 时使用） |

## 三、速度（实测，窗口 1821×1137）

| 操作 | 耗时 |
| --- | --- |
| PowerShell 一次批量动作（含启动） | ~0.9~1.2 秒 |
| 全窗口 OCR（Windows 内置 OCR，zh-Hans-CN） | **~0.15 秒** |
| 区域 OCR（含进程启动） | ~1.0 秒 |
| 像素哈希（判断页面是否变化） | ~0.2 秒（在批量动作里） |
| 打开课程（含翻页查找） | 6~12 秒 |
| 读章节列表 | ~1 秒 |
| 文档滚到底（按 PageDown 批次 + 哈希判稳） | 8~12 秒 / 份 |

> 对比：早期方案每帧 OCR 3.2 秒 + 每动作 1~2 秒，现在相同流程快 4~6 倍。

## 四、已验证可用

1. 启动客户端（必须清掉 `ELECTRON_RUN_AS_NODE`，否则它退化成 Node 静默退出）。
2. 左侧导航「课程」→ 课程列表（支持滚动查找课程）。
3. 点课程卡片 → 课程页 → 目录/章节列表（OCR 识别 `1.1`、`2.1` 这类编号）。
4. 点章节 → 任务点页面。
5. 任务点页面里 **点一下正文再按 PageDown 可以滚动**（鼠标滚轮事件在 Electron 内层不生效，键盘可以）。
6. 关闭「账号异常登录」提示弹窗（点「确定」）。

## 五、已知限制

- 页面内容（章节列表、正文）不在 UIA 树里，只能截图 OCR；OCR 会把全角标点、相似字识别错（如 `1.5` 识别成 `巧`），因此匹配要用归一化 + 编号容错。
- 视频在任务页的「视频」标签里；标签点击与播放控制仍需按 OCR 坐标点击，尚未验证完整播放计时。
- 每题一条的测验/作业页面还没有桌面端回填实现（网页版已有完整实现）。
- 桌面端操作会把客户端窗口提到前台，会打断用户同时用电脑。

## 六、结论与建议

- 桌面客户端适合做「打开客户端、进入课程、看任务点」这类**低频操作**；
- 高频的刷课计点、测验/作业作答，仍建议走插件已在网页版（Edge + CDP）跑通的链路——同样的账号、同样的任务点，网页版可以精确驱动视频播放、文档滚动、测验提交；
- 面板上「桌面版」= 打开本机客户端（当前已可用），「网页版」= 在 Edge 中自动化（服务端流程已完成）。
